# Project: threejs-game

A 3D multiplayer game using React, Three.js (React Three Fiber), Rapier physics, Zustand state management, and Geckos.io networking.

## Tech Stack
- **Frontend**: React 19, Three.js, React Three Fiber, @react-three/rapier, @react-three/drei, @react-three/postprocessing, Zustand, Vite
- **Networking**: Geckos.io (UDP/WebRTC), Geckos.io snapshot-interpolation
- **Server**: Node.js, Express, server/index.js, server/physics-worker.js
- **Testing**: Vitest (unit), Playwright (e2e)
- **Styling**: CSS, framer-motion

## Key Commands
- `npm install` — install dependencies
- `npm run dev` — start frontend (Vite, http://localhost:5173)
- `npm run server` — start multiplayer server (server/index.js)
- `npm run test` — run Vitest unit tests
- `npm run test:e2e` — run Playwright browser tests
- `npm run build` — production build (vite build)
- `npm run deploy` — build + deploy via deploy.cjs

## File Organization
- `src/components/` — React and R3F components, grouped by feature
- `src/components/Player/` — Character controller, model, animations
- `src/components/World/` — Arena, environment, obstacles
- `src/components/UI/` — Menus, HUD, overlays
- `src/store/` — Zustand stores
- `src/data/` — Static data (registries, configs)
- `src/utils/` — Helper functions (Logger, math, SoundManager, etc.)
- `src/hooks/` — Custom React hooks
- `server/` — Multiplayer server code
- `tests/` — Playwright e2e spec files

## Naming Conventions
- React components: `PascalCase.jsx` (e.g., `PlayerController.jsx`)
- Functions/variables: `camelCase` (e.g., `calculateSpeed`)
- Constants: `UPPER_SNAKE_CASE` (e.g., `MAX_HEALTH`)
- CSS classes: `kebab-case` (e.g., `game-hud`)
- Unit tests: `[name].test.js`
- E2E tests: `[name].spec.js`

## Multiplayer & Physics Rules
- The server (`server/index.js`) is authoritative — it keeps track of all player positions
- Players send moves to the server via Geckos.io; server broadcasts snapshots to all clients
- Physics bodies should be simple (boxes, capsules) for performance
- Don't move physics objects by changing position directly — use impulses or forces
- Remote player rotation comes from client's `camRot` broadcast in the snapshot
