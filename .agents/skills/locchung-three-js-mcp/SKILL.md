# Three.js MCP (locchung) Skill

This skill allows you to control a live Three.js scene straight from your code editor using the `three-js-mcp` server.

## Overview

The `three-js-mcp` server exposes several tools that communicate via WebSockets (on port 8082) to a connected Three.js client application. 
The client needs to be programmed to connect to `ws://localhost:8082` and handle the messages generated by the MCP server.

## Available Tools

- `getSceneState()`: Get the current scene state (returns a JSON string with an array of object data such as IDs, types, positions, colors). Always check the scene state before attempting to manipulate it.
- `addObject(type, position, color)`: Add a new object to the scene. position is `[x, y, z]`. Example: `addObject({ type: 'cube', position: [0, 1, 0], color: 'blue' })`.
- `moveObject(id, position)`: Move an existing object to a new position `[x, y, z]`. Ensure you get the correct `id` from `getSceneState()` first.
- `removeObject(id)`: Remove an existing object by its ID.
- `startRotation(id, speed)`: Start rotating an object around the y-axis at the given speed (radians per frame).
- `stopRotation(id)`: Stop the rotation of the specified object.

## Best Practices
1. **Integration**: Your Three.js application MUST have a WebSocket client connecting to `ws://localhost:8082`. The client is responsible for interpreting the messages (e.g. `{ action: 'addObject', type: 'cube', position: [0,0,0], color: 'red' }`) and executing them in the actual Three.js scene.
2. **Identification**: Always use the `getSceneState()` tool to retrieve valid Object IDs before attempting to move, rotate, or remove them.
3. **Connectivity**: If tools return "No client connection available", ensure your Three.js application is running and the WebSocket has connected properly.
