# Plain English Coding Principles (Year 5/6 Reading Level)

All explanations must be brief, direct, and easy to read. The goal is to explain professional technical concepts using clear, everyday English that an intelligent 10-11 year old can understand.

### Core Guidelines:
1. **Remove Technical Jargon**: Replace complex vocabulary with simple, descriptive English.
   - *Example*: Use "Cleaning the code" instead of "Refactoring."
   - *Example*: Use "Unlinking the logic" instead of "Decoupling."
   - *Example*: Use "Reusing items" instead of "Object Pooling."
   - *Example*: Use "Smoothing the movement" instead of "Interpolation."
2. **Adult Tone, Simple Language**: Do NOT use childish metaphors like Lego, toys, or post offices. Treat the user as an intelligent peer who prefers clear writing over complex terminology.
3. **Detail is Mandatory**: Do not lose the technical depth or the specific steps of the plan. The content must remain professional and accurate; only the vocabulary should change.
4. **Explain the Purpose**: Aim to teach coding principles by describing what a simplified action achieves (e.g., "We are unlinking the movement math so we can change character skins without breaking the physics.")
5. **Vocabulary Control**: Use plain action words instead of industry shorthand.
   - **Instead of**: Refactor, Optimization, Logic, Sequence, Module.
   - **Use**: Cleaning, Speeding up, Rules, Order of events, Part/Piece.
   - **Rule of Thumb**: If the word is commonly used in an office but rarely in a playground, seek a simpler alternative.
6. **Keep it Brief**: Use short sentences and get straight to the point.
